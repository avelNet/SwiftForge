# Архитектура SwiftForge MVP

## Цель

На Ubuntu разработчик открывает SwiftUI-проект, редактирует его с подсказками по iOS API, собирает IPA и видит запущенное приложение на физическом iPhone в панели SwiftForge. В первой версии панель входит в обязательный сценарий. Windows, симулятор, публикация и полноценная отладка выходят за рамки этого этапа.

Уже подтверждены SwiftUI-сборка через xtool 1.24.0 и Swift 6.4.2 с SDK из Xcode 27.2, подпись и установка через iLoader, зеркалирование через UxPlay. Доказываем связь этих компонентов в IDE и повторяем тест с чужим проектом.

## Системы и ветки

| Ветка | Что поставляет | Как проверить |
| --- | --- | --- |
| `docs/mvp-architecture` | Архитектура и план приёмки | Согласовать первую версию и границы поддержки |
| `feat/ide-shell` | Tauri 2, React, TypeScript, Monaco, рабочая папка, файловый редактор и сохранение | Открыть SDKProbe, открыть Swift-файл, изменить и сохранить его |
| `feat/iphone-mirror` | Приёмник UxPlay, локальный видеопоток и панель iPhone | Подключиться через «Повтор экрана», нажать Increment на телефоне и увидеть изменение в IDE |
| `feat/swift-language` | SourceKit-LSP, подключение BSP xtool, подсказки, диагностика и навигация | В iOS-проекте получить подсказки SwiftUI и перейти к определению |
| `feat/ios-build` | Проверка инструментов, шаблон SwiftPM, запуск xtool, вывод и экспорт IPA | Создать проект и получить проверяемый IPA прямо из IDE |
| `feat/iphone-deploy` | Выбор устройства, передача IPA в iLoader и проверка установки по USB | Установить IPA, открыть приложение и связать результат с его идентификатором |
| `test/external-swiftui-workflow` | Прогон внешнего проекта и отчёт о совместимости | Изменить экран, собрать, установить и увидеть изменение через панель |

Первый кодовый PR можно проверить поверх документации. Ветки компонентов создаются от актуального `main` после появления оболочки или от её ветки, если нужна параллельная проверка. В таком случае PR открывается к ветке зависимости до её слияния. Перенос в `main` выполняет владелец проекта после проверки.

## Как работает IDE

- **Редактор.** Интерфейс хранит модель Monaco для каждого открытого файла, определяет несохранённые изменения и отправляет Rust операции чтения и сохранения. Настольный выбор папки задаёт рабочую область. Rust проверяет пути и ограничивает операции выбранной областью.
- **Язык.** Rust запускает SourceKit-LSP для активного проекта. Monaco передаёт изменения документов по LSP и отображает ответы. Для SwiftPM-проекта iOS сервер использует BSP xtool и параметры того же SDK, что при сборке. Приёмка включает hover, completion, diagnostics и переход к определению для SwiftUI.
- **Сборка.** Rust запускает `xtool dev build --ipa` с явно заданными аргументами и рабочим каталогом. Логи идут в панель по мере работы. Отдельно отображаем ошибки SDK, компиляции и упаковки. Результат содержит путь, bundle ID и статус. Учётные данные Apple остаются в iLoader.
- **iPhone.** USB нужен для обнаружения, установки и проверки. AirPlay нужен для видео. Касания выполняются на iPhone. Для встраивания проверяем локальный вывод UxPlay через GStreamer и передачу кадров панели через loopback. Приёмник и видео работают только после явного запуска пользователем. Запись экрана не нужна. Ветка зеркала считается готовой после появления изображения внутри IDE.
- **Среда.** Первая поддерживаемая конфигурация — Ubuntu и SwiftPM с `Package.swift` и `xtool.yml`. Apple SDK устанавливается из локального официального Xcode. Архив, SDK, provisioning profiles и локальные пути инструментов не входят в репозиторий или дистрибутив IDE. Условия использования SDK проверяем отдельно перед коммерческой поставкой.

## Приёмка

1. Из чистой Ubuntu открыть SDKProbe и получить подсказку для `Text` из SwiftUI.
2. Изменить видимый текст и сохранить файл. Вызвать ошибку компиляции, открыть её строку и исправить.
3. Собрать IPA из IDE, установить через рабочий процесс iLoader и открыть приложение на iPhone.
4. Увидеть изменённый экран внутри SwiftForge. Нажать кнопку на iPhone и увидеть обновление в панели.
5. Повторить с внешним GitHub-проектом. Зафиксировать URL и коммит, исходный формат, адаптацию и результат открытия, LSP, сборки, установки и запуска. Отдельно отметить ресурсы и зависимости. Для проекта Xcode вести отдельный результат импорта.

Первый внешний проект берём на SwiftPM с ресурсами или внешней зависимостью. Затем проверяем обычный `.xcodeproj` с одним iOS-таргетом. Сам факт открытия папки не считается успешной сборкой проекта.
